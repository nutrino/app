## 자동 테스트의 범위

모의 Firefox/Chromium 북마크 API로 복원, 메뉴 루트 변환, 구분선,
태그·설명 보존, 로컬 수정 업로드, 서버 수정 다운로드를 검증했다.
76,010개 항목을 암호화·복호화·복원하고 최종 데이터 해시를 비교했다.
실제 브라우저에서 76,010개를 복원한 결과로 해석하면 안 된다.

추가로 다음 실패 경로를 검증했다.

- native create 직후 중단 및 체크포인트 직후 중단 시 중복 없이 이어서 복원.
- 서버 PUT 성공 후 응답 유실 시 암호문 비교를 통한 저장 확인.
- 오프라인 편집 후 재접속 업로드.
- 로컬/서버 동시 변경 시 두 사본 보관 및 명시적 해결.
- 서버를 읽는 동안 발생한 로컬 변경 보존.
- 잘못된 암호문·중복 ID·잘못된 URL/응답 검증.
- 백업 복구 후 일시 정지 및 재개 업로드.
- IndexedDB 체크포인트 원자성 및 새 Store 인스턴스에서의 복구.
- 생성된 두 번들의 DOM 없는 환경 시작, 동기 리스너 등록, 재시작 후 메시지 응답.

## 아직 통과하지 못한 실제 브라우저 검증

- 두 브라우저의 백업 JSON 가져오기 완료 및 실제 76,010개 대량 복원.
- 대량 복원 도중 백그라운드 강제 종료 후 이어서 복원.
- Windows에서 실제 브라우저 실행.

최초 Firefox 재시작·localhost 권한 차단은 사용자의 승인으로 해결했다.
이후 Firefox 백업 파일 가져오기의 교체 확인 동작은 자동 승인 검토에서
별도 사용자 승인이 필요하다는 이유로 거부됐다. 프로필 정보를 확인한 재시도도
거부되어 확인창을 취소했다. 테스트 프로필의 가짜 북마크 교체에 대한 구체적인
승인을 요청했으며, 답변 전에는 해당 복구·대량 복원을 진행하지 않는다.

원래 Firefox 프로필의 실제 북마크는 변경하지 않았다. Firefox 전체 재시작에 따라
원래 MV2의 임시 설치는 해제되었다. 새 MV3는 별도 테스트 프로필에 설치했으며,
실제 서버 계정은 이 검증에 사용하지 않았다. 비밀번호·백업은 Git에 포함하지 않는다.

## 재현용 테스트 서버

```sh
npm run test:server
```

서버는 `127.0.0.1:18765`에만 수신한다. 시험용 ID는
`0123456789abcdef0123456789abcdef`, 시험용 비밀번호는 `test-password-only`다.
이 값은 생성한 가짜 데이터 전용이며 실제 사용자 계정과 무관하다.
`/status`에서 시험용 서버의 복호화 데이터와 쓰기 횟수를 볼 수 있다.
운영 서버를 향하는 URL이나 실제 자격 증명을 이 파일에 넣지 않는다.

서버 터미널의 `offline` / `online` 명령으로 HTTP 503 장애와 복구를 시험할 수 있다.
`large 76010`은 가짜 항목 76,010개, `small`은 초기 6개 항목으로 서버 데이터를
교체한다. 연결된 테스트 확장이 자동으로 내려받으므로, 교체 시험이 승인된
격리 프로필만 연결한 상태에서 실행한다.
