## 남은 배포·환경 제약

- Windows에서 실제 브라우저 실행은 미검증이다. Windows CI의 빌드·자동 시험은 성공했다.
- Firefox ZIP은 Mozilla 서명 전 빌드다. 임시 설치는 Firefox 종료 시 해제된다.
- 이번 실제 MV3 통합 시험은 localhost 가짜 계정으로 진행했으며,
  운영 서버의 실제 계정으로 새 MV3를 전환하는 작업은 수행하지 않았다.

Firefox 재시작·localhost 권한 및 테스트 북마크 교체에 대한 사용자의 구체적인
승인을 받은 후, 위 두 테스트 프로필에서만 복구·대량 복원 시험을 진행했다.
기존에 자동 승인 검토로 중단했던 백업 가져오기도 이번 승인 후 완료했다.

원래 Firefox 프로필의 실제 북마크는 변경하지 않았다. Firefox 전체 재시작에 따라
원래 MV2의 임시 설치는 해제되었다. 새 MV3는 별도 테스트 프로필에 설치했으며,
실제 서버 계정은 이 검증에 사용하지 않았다. 비밀번호·백업은 Git에 포함하지 않는다.

## 실제 계정의 Chrome 복원 비교 오류 수정

사용자가 81,462개 실제 계정 복원의 마지막 비교 오류를 보고했다.
확장 내부의 저장된 대상·생성 매핑과 native 북마크를 읽는 진단 기능을 추가하고,
누락·추가·순서·부모·제목·URL·메타데이터 차이를 값 노출 없이 집계했다.
Chrome에서 남은 차이는 URL 한 개였으며, Firefox의 `about:reader?...`가
`chrome://reader/?...`로 저장되는 변환이었다.

Chrome에 한해 이 변환을 인식하면서 원래 동기화 URL을 보존하도록 수정했다.
같이 발견한 제목의 줄바꿈·탭·Unicode 구분자 공백 변환도 원본을 보존한다.
실제 외부 수정이나 다른 URL·쿼리 차이는 계속 오류로 처리한다.

현재 설치를 새로고침한 후 읽기 전용 진단에서 81,462개 전체 일치를 확인했다.
‘동기화 재개’로 마지막 체크포인트의 전체 해시 검사를 완료했고,
‘동기화 사용 중’ 정상 상태가 표시됐다. 북마크 삭제·재생성 없이 복구했다.
서버 저장 시각 표시도 기존 값으로 유지됐다. 운영 계정의 자격 증명과 북마크 원문은
소스·테스트·Git에 포함하지 않았다. 위 초기 시험의 운영 계정 미검증 범위는
이번 실제 복원 오류 복구 결과와 구분한다.

자동 테스트 23개, 문법 검사, Firefox·Chromium ZIP 생성 통과.
새 회귀 테스트는 가짜 읽기 모드 주소와 공백 포함 제목을 사용하며,
진단이 서버/복원 상태를 변경하지 않고 실제 수정은 계속 검출함을 확인한다.

## Firefox 기존 북마크 정리 지연 수정

Firefox의 `복원 중 (0/81459)` 보고를 확인했다. 새 항목을 생성하기 전에
기존 시험 북마크 76,007개를 정리하는 중이었으나 화면은 생성 진행률만 표시했다.
같은 폴더의 앞 항목부터 삭제하던 순서를 뒤에서부터 삭제하도록 바꾸고,
8개씩 완료를 기다린 뒤 체크포인트를 저장하도록 개선했다. 중단된 이전 빌드의
계획은 남은 ID만 재배열하며 원래 백업과 대상 데이터는 유지한다.
삭제 도중 종료돼도 이미 사라진 ID를 건너뛰며 이어가는 회귀 시험을 추가했다.

화면에 ‘기존 북마크 정리 중’의 실제 진행률을 표시한다. IndexedDB 복원 기록은
getAllKeys/getAll 두 요청으로 읽고 완료 기록은 IDBKeyRange로 일괄 정리한다.
한 행마다 이벤트가 발생하는 커서 방식의 반복 비용을 줄였다. 서로 다른 복원의
기록 및 백업이 유지되는 것을 자동 시험으로 검증했다.

Firefox에 수정 빌드를 로드하여 정리가 26,178/76,007개까지 진행되는 것을 확인했다.
Firefox 자체 북마크 Sync는 꺼져 있었다. 설치된 Bookmark Info의 공식 최신 배포
2.26.4 소스에서는 새 북마크를 index 0으로 이동하고 새 폴더도 재정렬하는 동작을
확인했다. 당시에는 간섭 가능성을 우려하여 생성 단계 진입 전에 복원을 일시 정지했다.
이는 설치된 버전에서 실제 간섭을 재현한 결과는 아니며, 다른 확장의 중지를 복원
재개의 필수 조건으로 판단할 근거는 부족했다. 아래 후속 검증에서는 설정을 그대로
둔 채 전체 복원을 완료했다.
자동 테스트 27개, 문법 검사와 두 브라우저 패키지 생성은 통과했다.


추가로 긴 복원 도중 알람이 중복 실행 요청을 대기열에 쌓아 일시 정지가 늦어지는
문제를 수정했다. 진행 중인 run Promise를 공유하여 겹치는 요청을 합친다.
두 브라우저의 실제 번들 시험에서 50개 알람을 겹쳐도 native 조회가 한 번만
실행되고 일시 정지가 완료되는 것을 검증했다. 현재 Firefox에서도 수정 빌드로
다시 로드한 후 일시 정지를 눌러 현재 청크 종료 후 ‘동기화 재개’ 버튼으로
바뀌고 진행 위치가 보존되는 것을 확인했다. 원래 백업과 서버 복원 대상은 유지한다.

## Firefox 실제 계정 복원 완료 — 2026-09-15

사용자의 계속 진행 요청에 따라 QuickBookmarkToFolder와 Bookmark Info 등 다른
확장의 설정을 변경하지 않고 기존 체크포인트에서 복원을 재개했다.
QuickBookmarkToFolder는 사용자가 현재 페이지를 북마크에 추가하는 확장으로,
다른 북마크 동기화 확장으로 취급하지 않는다.

기존 북마크 정리 76,007개를 마친 뒤 81,459개 생성이 끝나고, 기본 루트 3개를 포함한
총 81,462개 전체 해시 비교가 통과했다. Firefox 화면이 ‘동기화 사용 중’으로
전환됐으며, 서버의 마지막 저장 시각은 복원 전과 동일하게 유지됐다.
이 환경에서 다른 확장의 간섭으로 인한 복원 불일치는 재현되지 않았다.
Chrome에서도 같은 81,462개 항목과 ‘동기화 사용 중’ 상태를 확인했다.
두 브라우저에서 ‘지금 동기화’를 실행한 후에도 오류와 서버 저장 시각 변경 없이
정상 상태를 유지하는 것을 확인했다. 이번 추가 검증에서는 북마크 내용이나 다른
확장의 설정을 임의로 변경하지 않았다.

## 최초 연결 권한과 입력값 저장 개선 — 2026-09-15

이전 화면은 연결 제출 시 권한을 요청하여 팝업이 닫히면 후속 연결이 끊길 수 있었고,
URL 자동완성을 사용하면서 입력값을 자체 저장하지 않았다. 최초 설치와 미연결
팝업 진입 시 설정 탭을 열고, 서버 주소에 대한 권한을 계정 입력보다 먼저 요청한다.
권한 승인 후에는 해당 탭에서 한 번의 연결 제출로 서버 데이터를 확인한다.
새 서버로 변경하거나 권한이 취소된 경우 다시 권한 단계로 전환한다.

주소와 ID는 storage.local, 비밀번호는 storage.session에 저장한다. 입력 이벤트마다
저장하고 빠른 입력의 저장 순서를 보장하며, 화면 초기화 시 저장값을 복원한다.
브라우저 URL 자동완성을 끄고 전용 필드 이름을 사용한다. 특정 CGV 주소의 출처를
직접 재현한 것은 아니며, 소스에 해당 주소를 기본값으로 저장하는 코드는 없었다.
비밀번호는 사용자 선택에 따라 브라우저 재시작 후에는 복원하지 않는다.

Firefox Developer Edition 157의 별도 xbs-setup-test 프로필과 Chrome에서 테스트용
임시 확장을 설치하여 설정 탭 자동 열림, localhost 한정 권한 요청, 권한 승인 직후
계정 입력 단계 전환, 새로고침 후 주소·ID·비밀번호 유지, 단 한 번의 연결 제출로
가짜 계정의 6개 항목 미리보기 도달을 확인했다. 복원 버튼은 누르지 않았으며,
테스트 확장을 제거하고 로컬 테스트 서버를 종료했다.

자동 테스트 32개, 문법 검사, Firefox·Chrome 배포용 ZIP 생성 통과. 추가 시험은
권한 거절·취소, 연결 실패 시 입력 보존, 세션 종료 시 비밀번호만 초기화,
이전 권한 조회 응답의 역전, 기존 연결 주소 이전, 설치 때만 설정 탭 열기를 검증한다.

권한 요청은 [브라우저의 사용자 동작 요건](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/permissions/request)에
따라 초기 설정 화면의 버튼에서 수행한다. 주소를 입력하기 전 모든 사이트의 권한을
한꺼번에 요청하지 않는다.

## Windows Firefox의 순서 88개 차이 보고 대응

사용자가 81,462개 복원 마지막 검사에서 ‘순서 88개’ 차이를 보고했다. 이 보고는
내용과 부모가 같은 항목의 형제 순서가 다르다는 의미이며, Windows 자체나 특정
확장이 원인이라고 확정할 자료는 없다. 기존 생성 코드는 각 create 완료를 기다리지만,
완료 시 순서가 달라진 경우를 복구하지 않고 중단했다.

전체 비교 결과가 순서 차이만 있을 때 기존 생성 매핑과 계획으로 해당 폴더의
순서를 재조정한다. native move를 한 번씩 기다리며 동일 부모 내에서만 이동한다.
폴더의 실제 ID 집합도 이동 직전에 검사한다. 진행 기록은 이동 전에 저장하여
응답 유실이나 중단 후에도 실제 순서를 다시 읽어 이어간다. 폴더 중간에도 시간
예산에 따라 반환하며, 다음 청크에서 전체 내용 비교를 다시 수행한다.
두 차례 조정 및 이동 횟수 상한으로 지속적인 외부 변경에 따른 무한 반복을 막는다.
최종 전체 해시 비교는 유지하고, 기존 백업과 서버 내용은 변경하지 않는다.

수동 재개 시 오래된 오류를 지워 정상 청크의 후속 실행이 지연되지 않도록 했다.
수동 재개는 순서 복구의 재시도 한도도 새로 부여하되 진행 위치는 보존한다.

Firefox·Chrome 모델에서 88개 순서 차이를 재현하여 재생성·업로드 없이 복구함을
검증했다. 이동 직후 응답 유실, 폴더 중간 중단 및 새 Engine에서 재개, 내용 차이
동반 시 보존, 검사 후 폴더 구성 변경, 계속되는 재정렬의 제한 종료, Chrome의
Other 안 Menu 래퍼 순서도 시험했다. 자동 테스트 40개, 문법 검사 및 두 ZIP 빌드 통과.
Windows 11 실제 브라우저에는 여기서 접근할 수 없으므로 사용자 환경의 원인 재현과
수정본 적용 후 완료 여부는 아직 확인하지 않았다.

API 근거: [Mozilla bookmarks.move](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/bookmarks/move).

## 적용 빌드 식별 및 실행부 비교

이후 사용자는 재개 후 다시 멈춘 상황에서 실제로 최신 버전을 반영하지 않았다고
확인했다. 최신 순서 복구 코드가 실행됐는데도 같은 오류가 재발한 것으로 취급하지 않는다.

빌드 시 Git HEAD 커밋 해시·committer 시각, 미커밋 변경 여부, 런타임 소스와 빌드
입력의 SHA-256 지문, 빌드 시각을 화면과 실행부 번들에 동일하게 포함한다.
배포 파일을 덮어써도 실행 중인 코드의 정보가 바뀌지 않도록 정적 JSON을 실행 시
읽는 방식 대신 번들 상수로 삽입한다. build-info.json도 ZIP에 포함하여 배포본을
따로 확인할 수 있다. Git 정보가 없는 압축본도 정보 확인 불가를 명시하며 빌드된다.

화면은 로드 직후 자기 정보를 표시하고, 1.5초 상태 갱신마다 실제 실행부 정보를
받아 비교한다. 커밋·소스 지문·빌드 시각·플랫폼 중 하나라도 다르거나 구버전
실행부라 정보가 없으면 재로드 안내를 표시한다. 복원 단계·생성 위치·순서 조정
시도와 이동 횟수도 표시한다. 서버 자격 증명이나 북마크 내용은 포함하지 않는다.

자동 테스트 41개와 문법 검사를 통과했다. 두 실제 번들의 status 응답을 생성된
build-info.json과 비교하고, 화면 번들의 동일 지문·시각 포함, 빌드 불일치 및
메타데이터 미제공 시 표시도 검증했다.
