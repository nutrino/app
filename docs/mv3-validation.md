# MV3 validation record

검증일: 2026-09-14–15. 대상: `mv3-codex`의 1.8.1 후보 빌드.

- `npm ci --ignore-scripts`: 현재 의존성 집합 설치 성공.
- `npm test`: 19개 자동 테스트 통과. 테스트 전에 두 브라우저용 번들을 생성한다.
- `npm run lint`: 새 실행부의 문법 및 금지된 실행 API 검사 통과.
- Firefox / Chromium 프로덕션 빌드와 ZIP 생성 성공.
- `npm audit`: 알려진 취약점 0개. 이는 악성 코드 부재 또는 무결점 보증이 아니다.
- Firefox Developer Edition 155.0에서 MV3 manifest 임시 로드 성공.
- Firefox 확장 목록에서 위성 아이콘 클릭 → 팝업 표시 → 전체 페이지 표시 성공.
- Firefox에서 로컬 테스트 서버에 대한 선택적 호스트 권한 요청 표시 성공.
  권한 거부 시 오류 안내가 표시되고 북마크는 변경하지 않는다.

## 자동 테스트의 범위

모의 Firefox/Chromium 북마크 API로 복원, 메뉴 루트 변환, 구분선,
태그·설명 보존, 로컬 수정 업로드, 서버 수정 다운로드를 검증했다.
76,010개 항목을 암호화·복호화·복원하고 최종 데이터 해시를 비교했다.
실제 브라우저에서 76,010개를 복원한 결과로 해석하면 안 된다.

추가로 다음 실패 경로를 검증했다.

- native create 직후 중단 및 체크포인트 직후 중단 시 중복 없이 이어서 복원.
- 서버 PUT 성공 후 응답 유실 시 암호문 비교를 통한 저장 확인.
- 오프라인 편집 후 재접속 업로드.
- 로컬/서버 동시 변경 시 두 사본 보관 및 명시적 해결.
- 서버를 읽는 동안 발생한 로컬 변경 보존.
- 잘못된 암호문·중복 ID·잘못된 URL/응답 검증.
- 백업 복구 후 일시 정지 및 재개 업로드.
- IndexedDB 체크포인트 원자성 및 새 Store 인스턴스에서의 복구.
- 생성된 두 번들의 DOM 없는 환경 시작, 동기 리스너 등록, 재시작 후 메시지 응답.

## 아직 통과하지 못한 실제 브라우저 검증

- Firefox의 실제 서버 연결, 양방향 동기화, 백그라운드 종료 후 복원 재개.
- Chrome의 확장 설치·팝업·서버 연결·양방향 동기화·워커 종료 후 재개.
- 두 브라우저 간 왕복 수정, 실제 대량 복원 및 백업 다운로드/복구.
- Windows에서 실제 브라우저 실행.

테스트를 위해 Firefox의 `xbs-mv3-test` 프로필을 만들었으나 별도 프로필 창을
현재 제어 도구에서 선택하지 못했다. 기존 기본 프로필은 유지했다.
전체 Firefox 종료는 기존 탭·세션을 중단할 수 있다는 이유로 자동 승인 검토가
거부했다. 새 확장에 `http://127.0.0.1:18765` 테스트 서버 접근 권한을 주는
작업도 승인 범위 부족으로 거부됐다. 이후 권한 요청은 거절하여 취소했다.
Chrome 프로필 추가 창은 접근성 내용과 스크린샷을 반환하지 않았다.

기존 Firefox MV2 확장과 실제 북마크는 유지된다. 추가한 MV3 확장은 별도 ID이며
계정 연결이 완료되지 않아 자동 동기화하지 않는다. 실제 서버 계정은 테스트에
사용하지 않았으며 비밀번호·백업을 Git에 포함하지 않는다.

## 재현용 테스트 서버

```sh
npm run test:server
```

서버는 `127.0.0.1:18765`에만 수신한다. 시험용 ID는
`0123456789abcdef0123456789abcdef`, 시험용 비밀번호는 `test-password-only`다.
이 값은 생성한 가짜 데이터 전용이며 실제 사용자 계정과 무관하다.
`/status`에서 시험용 서버의 복호화 데이터와 쓰기 횟수를 볼 수 있다.
운영 서버를 향하는 URL이나 실제 자격 증명을 이 파일에 넣지 않는다.
