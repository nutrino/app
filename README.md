# xBrowserSync MV3 desktop client

`mv3-codex` 브랜치의 Firefox·Chrome용 MV3 구현입니다. 기존 서버의
PBKDF2 / AES-GCM / LZUTF8 형식을 유지하며, AngularJS 없이 동작합니다.

**검증 상태:** macOS의 Firefox Developer Edition 156과 Chrome 152에서 팝업,
브라우저 간 양방향 동기화, 백업 다운로드·복구, 76,010개 실제 복원과 복원 도중
백그라운드 종료 후 재개를 확인했습니다. Windows·macOS·Linux CI도 통과했습니다.
Windows 브라우저의 직접 실행은 미검증이며, Firefox ZIP은 서명 전 빌드입니다.
자세한 범위는 [검증 기록](docs/mv3-validation.md)을 확인하세요.

## 빌드

Node.js 22 이상이 필요합니다. Windows, macOS, Linux에서 같은 명령을 사용합니다.

```sh
npm ci --ignore-scripts
npm test
npm run lint
npm run build:firefox:dev
npm run build:chromium:dev
npm run package:firefox
npm run package:chromium
```

- Firefox: `build/mv3/firefox/manifest.json`을 `about:debugging`에서 임시 로드합니다.
- Chrome: `chrome://extensions`의 개발자 모드에서 `build/mv3/chromium` 폴더를 로드합니다.
- 배포 ZIP: `dist/xbrowsersync-mv3-{firefox,chromium}-1.8.1.zip`.
- 기존 `build/firefox` MV2 설치 파일은 덮어쓰지 않습니다.
- Firefox ID는 `mv3@nutrino.xbrowsersync`이며 기존 확장과 저장 공간이 분리됩니다.
  두 확장을 같은 북마크에 동시에 연결하지 마세요. 전환할 때 기존 동기화를 먼저 중지합니다.
- Firefox 임시 설치는 브라우저 종료 시 제거됩니다. 일반 Firefox의 영구 설치에는
  Mozilla 서명이 필요합니다. 이 저장소의 ZIP은 서명된 스토어 배포본이 아닙니다.

## 기존 서버에 연결

확장 화면 상단에는 화면과 실행부 각각의 Git 최종 커밋·커밋 수정 시각(KST),
소스 지문·빌드 시각이 표시됩니다. 두 빌드가 다르면 재로드 안내가 나타납니다.
실행부 정보와 복원 단계·순서 조정 횟수는 화면을 연 동안 자동 갱신됩니다.
커밋하지 않은 수정으로 빌드했다면 별도 표시하며, Git 정보가 없는 소스 압축본은
‘확인 불가’로 표시합니다. 이 정보는 빌드 시 고정되며 GitHub에 조회하지 않습니다.

1. 최초 설치 시 열리는 설정 탭에서 서버 URL을 입력하고 **서버 연결 권한 허용**을 누릅니다.
2. 브라우저의 권한 요청을 허용한 뒤 기존 동기화 ID·비밀번호를 입력합니다.
3. **연결 및 서버 데이터 확인**을 누릅니다. 이미 허용한 서버 권한을 다시 요청하지 않습니다.
4. **동기화 방식**에서 서버 → 로컬, 로컬 → 서버, 양방향 중 선택하고
   **선택한 방식으로 최초 동기화**를 누릅니다. 서버에 자료가 있으면 서버 → 로컬,
   빈 서버이면 로컬 → 서버가 기본 선택됩니다.
5. 복원이 끝날 때까지 브라우저의 북마크를 편집하지 않습니다.

미연결 팝업에서는 로컬 폴더 검색과 **서버 연결 설정 열기** 버튼을 제공합니다.
서버 주소와 ID는 입력할 때
이 기기에 자동 저장합니다. 비밀번호는 확장의 세션 저장소에만 보관하므로 화면을
닫거나 새로고침해도 유지되지만 브라우저 종료 또는 확장 재로드 시 지워집니다.
연결 실패 시 입력값을 지우지 않습니다. 확장에 저장한 주소를 복원하고, 서버 주소
입력란에서는 브라우저 URL 자동완성도 허용합니다. 기존 연결이 있는 경우 그 주소와
ID를 저장값으로 이전합니다.

기존 xBrowserSync 1.5–1.8의 버전 정보가 있는 계정을 지원합니다. 신규 서버 계정
생성, 비밀번호 변경, Android UI는 이번 PC 클라이언트의 기능에 포함되지 않습니다.
태그·설명은 서버에 보존하며 브라우저에서 제목·주소·폴더·순서를 편집해 동기화합니다.

최초 내려받기는 같은 부모 폴더 안의 폴더 이름과 북마크 URL을 기준으로 항목을
대응시킵니다. 중복 URL도 개수를 유지하며, 제목만 다르면 수정하고 순서만 다르면
이동합니다. 폴더 이름이나 부모 위치가 달라 대응되지 않는 항목은 해당 부분만
교체할 수 있습니다. 전체가 같으면 브라우저 북마크 쓰기는 수행하지 않습니다.
새 ID 생성 자체는 기존처럼 서버/기존 클라이언트에서 수행해야 합니다.
선택한 방식은 저장되어 이후 수동·자동 동기화에도 적용됩니다. 기존 연결을 업데이트한
경우에는 기존 양방향 설정을 유지합니다. 연결 화면에서 방식을 바꿔 적용할 수 있으며,
복원 또는 서버 저장 확인 중에는 변경할 수 없습니다.

- **서버 → 로컬**: 서버를 기준으로 차이만 반영합니다. 서버에 없는 로컬 항목은
  로컬 백업 후 삭제하며, 로컬 변경을 서버에 올리지 않습니다.
- **로컬 → 서버**: 로컬 북마크를 그대로 두고 서버를 갱신합니다. 서버에만 있는
  자료는 덮어쓰므로 교체 전 서버 사본을 별도 보관합니다.
- **양방향**: 최초에는 같은 부모 안의 제목·URL이 같은 항목을 중복 개수만큼 대응시키고,
  같은 이름의 폴더를 합칩니다. 공통 항목은 서버 순서·메타데이터를 유지하고 로컬에만 있는
  항목을 추가합니다. 이후 양쪽이 동시에 변경되면 충돌 확인을 위해 정지합니다.

**서버 북마크 보기**에서 최근 추가 순과 폴더별 보기를 전환할 수 있습니다.
최근 순은 기존 xBrowserSync와 같은 서버 ID 내림차순이며, 서버 데이터에는 개별 추가
날짜가 없습니다. 폴더 보기는 서버의 구조와 순서를 유지합니다. 100개씩 표시하며
제목·주소·설명·태그로 검색할 수 있습니다(폴더 보기에서는 현재 폴더 범위).
새로 읽기 버튼으로 최신 서버 자료를 조회하며, 동기화 전이나 정지 중에도 이용할 수 있습니다.

## 현재 페이지를 폴더에 빠르게 추가

웹페이지에서 위성 아이콘을 누르면 팝업 맨 위에 **현재 페이지 북마크 추가**가 표시됩니다.
검색어를 입력하면 폴더 이름과 상위 경로를 검색하고 경로 이름순으로 나열합니다.
검색된 전체 개수를 표시하며 처음 50개 이후에는 더 보기로 이어서 확인할 수 있습니다.
폴더를 누르면 해당 로컬 폴더에 현재 페이지를 저장합니다. 동일한 URL이 이미 그 폴더에
있으면 중복 생성하지 않습니다. 서버 미연결 상태에서도 사용할 수 있습니다.
폴더를 다른 창에서 변경했다면 **폴더 새로 읽기**를 누르세요.

현재 페이지의 제목·주소는 아이콘을 누를 때 부여되는 `activeTab` 권한으로 읽습니다.
확장 설정 탭 자체를 북마크에 추가하지 않으므로 저장할 웹페이지에서 팝업을 여세요.
복원 중에는 추가를 막습니다. 서버 → 로컬 자동 동기화가 실행 중이면 로컬에 추가한
항목이 지워질 수 있으므로, 일시 정지 또는 양방향·로컬 → 서버로 변경한 후 추가하도록
안내합니다. 일시 정지 후 추가한 항목도 서버 → 로컬로 재개하면 서버 기준으로 처리됩니다.

## 데이터 보존과 복구

- 양방향 모드에서 양쪽이 변경되면 자동 덮어쓰기를 중단하고 로컬/서버 사본을 따로 보존합니다.
- 서버 저장 응답이 유실되면 같은 암호문이 저장됐는지 먼저 확인합니다.
- 복원 전 백업, 이전 백업, 복원 진행 위치를 IndexedDB에 기록합니다.
- 백업 메뉴에서 JSON 다운로드와 복구를 할 수 있습니다. JSON에는 비밀번호·키가
  없지만 북마크는 평문입니다. 확장을 제거하면 내부 백업도 없어지므로 필요한 사본은 내려받으세요.
- 복구 후 동기화는 정지됩니다. 복구 내용을 서버에 올리려면 로컬 → 서버 또는 양방향을
  선택한 후 재개하세요. 서버 → 로컬 상태로 재개하면 서버 자료가 다시 적용됩니다.
- Chrome에 계정용/로컬용 루트가 중복되거나 지원하지 않는 루트에 데이터가 있으면
  임의로 합치거나 지우지 않고 오류를 표시합니다.
- 최대 250,000개 항목, 150단계 깊이, 64 MiB 응답/복호화 데이터 제한이 있습니다.

## 보안 및 개발 범위

비밀번호는 로컬에서 키를 유도하는 데만 사용합니다. 암호화 키는 자동 동기화를
위해 확장 내부 DB에 저장되므로 OS 계정에 접근할 수 있는 공격자로부터의 보호를
보장하지 않습니다. 지정한 서버 이외의 분석·광고·업데이트 서비스로 통신하지 않습니다.
HTTP 서버도 지원하지만 TLS가 없으므로 ID·수정 시각 노출과 응답 재생 위험이 남습니다.

현재 빌드 진입점은 `src/mv3`, 테스트는 `tests/mv3`입니다. `src/modules`, `webpack`,
`res/android`, `package.legacy.json`은 이전 구현 참고용이며 새 패키지에 포함되지 않습니다.
이전 Android/릴리스 자동화와 README는 `docs/legacy`에 보관했습니다.

[실패 원인 및 보안 조사](docs/mv3-assessment.md) · [검증 기록](docs/mv3-validation.md)

## Chrome 복원 마지막 단계에서 오류가 발생한 경우

Chrome은 `about:reader?...` 같은 주소를 `chrome://reader/?...`로 바꾸고,
제목의 일부 공백 문자를 정규화합니다. 이 변환을 데이터 손상으로 오인하던
비교 로직을 수정했습니다. 원본 URL·제목은 동기화 데이터에 보존합니다.
Firefox 읽기 모드 자체를 Chrome에 구현하는 변경은 아닙니다.

이전 빌드에서 항목 생성이 끝난 뒤 비교 오류로 정지했다면:

1. 최신 코드를 빌드하고 `chrome://extensions`에서 **기존 확장의 새로고침**을 누릅니다.
2. 확장의 **복원 차이 확인**으로 저장된 대상과 현재 북마크를 비교합니다.
3. 차이가 없으면 **동기화 재개**를 누릅니다. 저장된 마지막 단계에서 검사를 완료합니다.

확장을 삭제하면 복원 진행 기록과 내부 백업도 삭제됩니다. 위 절차는 기존 설치를
유지한 채 적용합니다. 차이가 남으면 필드·항목 ID가 표시되며 무조건 성공으로 넘기지 않습니다.

복원 시작 후 생성 진행률이 0에 머물던 Firefox 문제도 수정했습니다. 새 빌드는
기존 북마크 정리와 새 북마크 생성을 구분해 표시하고, 많은 형제 항목을 정리할 때
끝에서부터 묶음 처리합니다. 진행 중인 이전 빌드도 기존 확장의 새로고침으로
진행 기록과 백업을 유지한 채 업그레이드할 수 있습니다.

## 복원 완료 직전 ‘순서’ 차이로 중단된 경우

내용·항목 수·부모 폴더는 같고 순서만 다르면, 새 빌드는 기존 북마크를 이동하여
서버의 순서로 맞춥니다. 삭제·재생성하거나 서버에 업로드하지 않으며, 이후 전체
해시 비교가 통과해야 동기화를 완료합니다.

Windows Firefox에서도 기존 확장을 제거하지 말고 설치에 사용한 파일을 최신 빌드로
갱신한 뒤 `about:debugging#/runtime/this-firefox`에서 해당 확장의 **새로고침**을
누르세요. 확장 화면에서 **동기화 재개**를 누르면 저장된 대상·생성 기록으로
순서 복구를 진행합니다. ‘복원 순서 조정 중’의 진행률은 처리한 폴더 수입니다.

제목·URL·부모·누락·추가 차이가 있으면 자동 순서 복구를 수행하지 않습니다.
순서를 맞춰도 반복해서 다시 바뀌면 두 차례 조정 후 중단합니다. 그 경우 표시된
차이를 확인하고, 실제 변경 원인을 해결한 후 다시 **동기화 재개**를 누르세요.
